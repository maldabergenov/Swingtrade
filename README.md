# swingscan — сканер акций США для swing-торговли

Приложение дважды в день сканирует рынок акций США, отбирает бумаги под
среднесрочные (2–3 недели) сделки и присылает отчёт в Telegram.

Второй, независимый режим — **ежедневный маркет апдейт** в 09:00 по Астане:
итоги прошлой сессии США, главные заголовки финансовых изданий и посты из X.
См. раздел [«Маркет апдейт»](#маркет-апдейт).

**Критерии из технического задания:**

| Параметр | Значение |
|---|---|
| Время сканов | 09:00 и 21:00 по Астане (`Asia/Almaty`, UTC+5) |
| Горизонт сделки | 10–15 торговых сессий (2–3 недели) |
| Минимальная потенциальная прибыль | **+20%** от цены входа |
| Максимальный риск на стоп-лосс | **2%** от цены входа |
| Минимальная цена акции | **$5** |
| Минимальная капитализация | **$50 млн** |
| Доставка | Telegram-бот |

---

## Важное предупреждение о связке «+20% при риске 2%»

Требования ТЗ означают соотношение прибыль/риск **10:1**. Это очень жёсткое
условие, и его нельзя обойти «подгонкой» цифр — сканер устроен так, чтобы
честно показывать реальность, а не рисовать красивые сделки:

* **Стоп всегда ≤ 2%.** Стоп ставится по структуре графика, но если структурный
  уровень дальше 2% — он подтягивается до лимита. Больше 2% риска сканер не
  выдаёт никогда.
* **Стоп не должен быть внутри дневного шума.** Стоп в 2% на бумаге с дневным
  диапазоном 5% выбьет вас случайным колебанием. Поэтому требуется
  `2% ≥ 0.75 × ATR%`, то есть ATR ≲ 2.7%.
* **Цель +20% должна быть достижима за 15 сессий.** Требуется
  `20% ≤ ATR% × 15`, то есть ATR ≳ 1.3%.

Вместе это даёт узкую рабочую полосу волатильности **ATR ≈ 1.3–2.7%** — только в
ней связка «+20% / −2%» физически реализуема. Плюс сетап проверяется на истории
самой бумаги (см. ниже). Поэтому:

> **Пустой отчёт — это нормальный, а не сбойный результат.** В спокойные периоды
> рынок может не давать ни одной конфигурации с таким перевесом. Сканер в этом
> случае присылает воронку отбора, чтобы было видно, на каком шаге всё отсеялось.

Порог безубыточности при R:R = 10:1 — всего **9% успешных сделок**: одна
достигнутая цель окупает десять стопов. Это и есть смысл такой асимметрии.

Если нужен более плотный поток идей — смягчите параметры в `.env`, например
`MIN_TARGET_PCT=0.12` и `MAX_RISK_PCT=0.03` (R:R = 4:1). Вся математика,
отчёты и фильтры пересчитаются автоматически.

## Быстрый старт

```bash
git clone <repo> && cd swingscan
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env         # и вписать токен бота
python -m swingscan telegram-test   # проверить связь с ботом
python -m swingscan scan --dry-run --limit 300   # пробный скан без отправки
python -m swingscan serve    # демон: сканы в 09:00 и 21:00 по Астане
```

### Настройка Telegram

1. Токен бота получают у [@BotFather](https://t.me/BotFather) и кладут в `.env`:
   `TELEGRAM_BOT_TOKEN=...`
2. `chat_id` можно не указывать: откройте бота в Telegram, отправьте ему
   `/start`, затем выполните `python -m swingscan telegram-test` — сканер сам
   определит чат и сохранит его в `state/telegram_chat.json`.
   Для группы или канала добавьте бота туда и укажите `TELEGRAM_CHAT_ID`
   вручную (у групп id отрицательный, например `-1001234567890`).

> **Безопасность.** Токен — это полный доступ к боту. Он хранится только в `.env`,
> который добавлен в `.gitignore` и никогда не попадает в репозиторий. Если токен
> где-то засветился (переписка, скриншот, публичный чат) — отзовите его в
> BotFather командой `/revoke` и выпустите новый.

## Команды

```bash
python -m swingscan scan               # разовое сканирование + отправка
python -m swingscan scan --dry-run     # то же, но без отправки в Telegram
python -m swingscan scan --no-cache    # игнорировать кэш котировок
python -m swingscan serve              # планировщик 09:00 / 21:00
python -m swingscan serve --run-now    # то же + скан сразу при старте
python -m swingscan schedule           # показать ближайшие запуски
python -m swingscan telegram-test      # проверить бота и отправить тест
python -m swingscan universe --refresh # обновить список бумаг
python -m swingscan --limit 100 scan   # ограничить вселенную (отладка)

python market_update.py                # маркет апдейт + отправка
python market_update.py --dry-run      # то же, но без отправки в Telegram
```

## Как работает отбор

### 1. Вселенная

Список торгуемых акций берётся из ежедневных справочников NASDAQ Trader
(`nasdaqlisted.txt` + `otherlisted.txt`) — это NASDAQ, NYSE, NYSE American и
другие площадки США, порядка 6000 бумаг. Отсеиваются ETF, тестовые выпуски,
варранты, юниты, права и привилегированные акции. Если справочники недоступны,
используется вшитый резервный список ликвидных бумаг.

### 2. Базовые фильтры

* цена закрытия ≥ $5 (и ≤ $5000 — защита от аномалий);
* средний объём ≥ 200 000 акций и ≥ $3 млн в день (чтобы позицию можно было
  реально набрать и выйти);
* капитализация ≥ $50 млн — запрашивается **только** у бумаг, прошедших
  предыдущие фильтры (десятки-сотни запросов вместо тысяч);
* минимум 200 дневных баров истории.

Бумага без подтверждённой капитализации не проходит: требование ТЗ должно
проверяться, а не предполагаться.

### 3. Фильтр тренда (общий для всех сетапов)

`цена > SMA50 > SMA150`, SMA50 растёт, `ADX(14) ≥ 18`, цена не ниже 25% от
52-недельного максимума и минимум на 30% выше 52-недельного минимума.

### 4. Сетапы

| Код | Название | Условия |
|---|---|---|
| `BO` | Пробой сжатой консолидации | диапазон 20 дней ≤ 18%, `ATR14 < ATR50`, цена у верхней границы базы, объём подсох (5д/20д ≤ 1.15) |
| `MOM` | Продолжение импульса | до 6% от годового максимума, +5% за 20 сессий, тугая полка (диапазон 10 дней ≤ 10%) |
| `PB` | Откат к скользящей | откат 3–15% от локального максимума, RSI 35–58, цена у EMA20 и выше EMA50, бар разворота |

### 5. Торговый план

* **Вход** — стоп-заявка выше уровня (`+0.1%` буфер на проскальзывание).
* **Стоп** — по структуре (минимум базы / последних баров), но не дальше 2%.
  Если структура даёт более тугой стоп — берётся он, и R:R получается выше 10.
* **Цель** — вход × 1.20.
* **Проверки реализуемости** — описаны выше (шум, достижимость, стоп ниже
  локального минимума).

### 6. Проверка на истории самой бумаги

По последним ~2 годам прогоняется **ровно то же правило входа**: стоп-заявка
живёт 3 сессии, стоп −2%, цель +20%, выход по времени через 15 сессий. Гэпы
исполняются по цене открытия, а бар, задевший и стоп, и цель, считается
убыточным — оценка сознательно консервативная. Идея отбрасывается, если на
истории у неё < 10% достижений цели или отрицательное матожидание. При малом
числе исторических сигналов идея не отбрасывается, но помечается в отчёте.

### 7. Оценка и ранжирование

Композитный балл 0–100: тренд (ADX), относительная сила против SPY, сжатие базы,
попадание ATR в рабочую полосу, близость к годовому максимуму, ликвидность,
фактический R:R и историческая статистика. В отчёт попадают топ-10 (`MAX_RESULTS`).

```
  • сжатие волатильности: ATR14/ATR50 = 0.83
  • объём подсох: 5д/20д = 0.82

📊 Воронка отбора
вселенная 5842 → с историей 5610 → цена 3204 → ликвидность 1480 →

```

Длинные отчёты автоматически режутся на части по 4096 символов. Полный JSON
каждого скана сохраняется в `reports/`.

### Про вечерний скан

* **09:00 Астаны** = 00:00 в Нью-Йорке: рынок США закрыт, последний дневной бар
  полный — самые надёжные сигналы.
* **21:00 Астаны** = 12:00 в Нью-Йорке: идёт американская сессия, последний бар
  ещё формируется. Сканер использует его как живой снимок и помечает отчёт
  «бар ещё формируется». Чтобы считать только по закрытым барам, поставьте
  `INCLUDE_PARTIAL_BAR=false`.

## Развёртывание

### Docker (рекомендуется)

```bash
cp .env.example .env    # вписать токен
docker compose up -d
docker compose logs -f swingscan
```

### systemd

```bash
sudo useradd -r -m -d /opt/swingscan swing
sudo cp -r . /opt/swingscan && cd /opt/swingscan
sudo -u swing python3 -m venv .venv
sudo -u swing .venv/bin/pip install -r requirements.txt
sudo cp deploy/swingscan.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now swingscan
journalctl -u swingscan -f
```

### GitHub Actions

В репозитории есть `.github/workflows/scan.yml` — сканы по cron 04:00 и 16:00
UTC (= 09:00 и 21:00 Астаны). Добавьте секреты `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_CHAT_ID` в настройках репозитория. Учтите: GitHub может запускать
задачи по расписанию с задержкой до нескольких десятков минут — для точного
времени используйте `serve` на своём сервере.

Планировщик устойчив к простоям: если машина спала в момент запуска, задача
выполнится при возвращении в строй в пределах 30 минут (`misfire_grace_time`).

Второй workflow — `.github/workflows/market-update.yml`, cron `0 4 * * 1-5`
(09:00 Астаны по будням): ежедневный маркет апдейт. Использует те же
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, остальные секреты опциональны —
подробности в разделе [«Маркет апдейт»](#маркет-апдейт).

## Маркет апдейт

Отдельная от сканера функция: раз в день, в **09:00 по Астане (04:00 UTC), по
будням**, в тот же Telegram-бот уходит сводка из трёх блоков.

* Скрипт: [`market_update.py`](market_update.py) (логика — в пакете
  `swingscan/marketupdate/`)
* Workflow: [`.github/workflows/market-update.yml`](.github/workflows/market-update.yml),
  cron `0 4 * * 1-5`
* Редактируемый конфиг: [`config/market_update.toml`](config/market_update.toml)

Доставка переиспользует `swingscan/telegram.py` — тот же `TelegramClient`,
те же секреты, та же нарезка сообщений по лимиту Telegram в 4096 символов.
Никакой второй реализации отправки в проекте нет.

**Почему только будни.** В субботу и воскресенье рынок США закрыт, и «итоги
прошлой сессии» дублировали бы пятницу. Если хотите получать сводку семь дней
в неделю, поменяйте cron на `0 4 * * *`.

### Блок 1 — итоги сессии

Индексы (S&P 500, Nasdaq Composite, Nasdaq 100, Dow Jones) и 11 секторных ETF
SPDR, из которых считаются топ-3 растущих и топ-3 падающих. Провайдеры
пробуются по порядку из `[market].providers`:

| Провайдер | Ключ | Особенности |
|---|---|---|
| `yfinance` | не нужен | Уже в зависимостях, знает настоящие индексы (`^GSPC`), один батч-запрос на все тикеры |
| `alphavantage` | `ALPHAVANTAGE_API_KEY` | Индексов нет — символы подменяются ETF-прокси (SPY/QQQ/DIA), запросы поштучно, free tier ограничен |

Строка «что двигало рынок» пишется LLM (см. ниже), а при её отсутствии
собирается из фактов: направление широкого рынка, лидер и аутсайдер, широта
движения по секторам.

### Блок 2 — новости

Открытые RSS, ключи не нужны: CNBC, MarketWatch, WSJ (Markets и Economy),
Financial Times. У Reuters и Bloomberg публичных лент не осталось — они
забираются через Google News RSS. Если задан `ALPHAVANTAGE_API_KEY`,
дополнительно подмешивается `NEWS_SENTIMENT`.

Отбор: окно `lookback_hours` (по умолчанию 16 ч) → дедупликация по
нормализованному заголовку → ранжирование по ключевым словам из
`[news.priority]` (макро, ставки, геополитика весят больше корпоративных
новостей) плюс бонус за свежесть → квота 2 заголовка на издание, чтобы быстрая
лента не заняла весь отчёт.

### Блок 3 — Twitter / X

**Бесплатного X API больше не существует.** По умолчанию блок выключен
(`[x].provider = "none"`) и уходит в отчёт с пометкой «раздел временно
недоступен» и подсказкой, какой ключ добавить. Список аккаунтов вынесен в
`[x].accounts` — редактируйте свободно, код трогать не нужно.

| `[x].provider` | Секрет | Что это |
|---|---|---|
| `none` | — | Блок отключён (по умолчанию) |
| `x_api` | `X_BEARER_TOKEN` | Официальный X API v2, `GET /2/tweets/search/recent`. Нужен платный тариф Basic ($200/мес) или выше |
| `twitterapi_io` | `X_API_KEY` | Сторонний twitterapi.io, тарификация по запросам |
| `apidance` | `X_API_KEY` | Сторонний apidance.pro |
| `rss` | — (нужен `[x].rss_base_url`) | Мост Nitter или RSSHub. Ключ не нужен, но публичные инстансы часто недоступны |

### Пересказ на русском

Заголовки приходят на английском. Чтобы они попадали в отчёт своими словами и
по-русски, делается **один** вызов Claude API на весь отчёт — модель получает
уже отобранные факты и возвращает по одной строке на заголовок плюс строку
контекста по рынку.

* Секрет: `ANTHROPIC_API_KEY`
* Модель: `[llm].model`, по умолчанию `claude-haiku-4-5` (порядка $0.001–0.003
  за запуск). Сменить можно в TOML или через `MARKET_UPDATE_LLM_MODEL`.
* Выключить целиком: `[llm].enabled = false` или `MARKET_UPDATE_LLM=false`.

Без ключа, без пакета `anthropic` или при сбое вызова отчёт всё равно уходит:
заголовки остаются на языке оригинала с тематической меткой (`[ставки]`,
`[инфляция]`, `[геополитика]` и т. д.), а в подвал добавляется примечание.

### Устойчивость к сбоям

Каждый из трёх блоков изолирован: падение источника превращается в секцию с
пометкой «раздел временно недоступен» и причиной, а не роняет отчёт. Ненулевой
код возврата — только если не собрался **ни один** из трёх блоков; частичный
отчёт считается штатным и workflow не краснеет.

### Секреты

| Секрет | Обязателен | Без него |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Отчёт только в лог и файл |
| `TELEGRAM_CHAT_ID` | нет | Определяется автоматически по `/start` |
| `ALPHAVANTAGE_API_KEY` | нет | Котировки берутся из yfinance, Alpha Vantage News пропускается |
| `ANTHROPIC_API_KEY` | нет | Заголовки на языке оригинала с тематической меткой |
| `X_BEARER_TOKEN` | нет | Нужен только для `[x].provider = "x_api"` |
| `X_API_KEY` | нет | Нужен для `twitterapi_io` / `apidance` |

Добавляются там же, где секреты сканера: **Settings → Secrets and variables →
Actions → New repository secret**.

## Конфигурация

Все параметры задаются через `.env` или переменные окружения — полный список с
комментариями в [`.env.example`](.env.example). Самое частое:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SCAN_TIMES` | `09:00,21:00` | Время сканов в `TIMEZONE` |
| `MIN_TARGET_PCT` | `0.20` | Минимальная потенциальная прибыль |
| `MAX_RISK_PCT` | `0.02` | Максимальный риск на стоп |
| `MIN_PRICE` | `5` | Минимальная цена акции |
| `MIN_MARKET_CAP` | `50000000` | Минимальная капитализация |
| `MAX_RESULTS` | `10` | Сколько идей слать в отчёте |
| `SEND_EMPTY_REPORT` | `true` | Слать отчёт, даже если идей нет |
| `MAX_SYMBOLS` | `0` | Ограничение вселенной (0 = без ограничения) |

## Ограничения

* Источник данных — Yahoo Finance (через `yfinance`), неофициальный API без
  гарантий доступности; сканер переживает сбои (повторы, кэш, пропуск бумаг),
  но при массовом отказе Yahoo отчёт будет пустым с предупреждением.
* Учитывается только техническая картина. Отчётности, новости, FDA-решения и
  прочие катализаторы **не анализируются** — проверяйте календарь событий перед
  входом: отчёт внутри горизонта сделки легко пробивает 2%-й стоп гэпом.
* Гэп через стоп исполняется хуже расчётного — реальный риск на сделку может
  превысить 2%. Это ограничение рынка, а не сканера.
* Блок X в маркет-апдейте требует платного доступа: бесплатного X API больше
  нет. Без ключа раздел приходит с пометкой о недоступности — это ожидаемое
  поведение, а не сбой.
* Заголовки в маркет-апдейте пересказываются кратко и могут терять нюансы —
  ссылка на первоисточник есть у каждой строки.
* Сканер работает только в лонг.
* **Это не инвестиционная рекомендация.** Решение о сделке принимаете вы.
